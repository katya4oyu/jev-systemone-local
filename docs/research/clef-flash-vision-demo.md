# Clef-Flash画像デモの動作確認

任意の静止画をブラウザで選び、ローカルのClef-Flash MLXへ送って表情の見え方を表示するデモを実装した。
既存のLaya、Core ML、Snakeのアプリとは別の起動モードで、既存の `/v1/systemone` 契約は変更していない。

## 判定と表示

JPEG、PNG、WebPの静止画を1枚入力する。
入力上限は4 MiB、1,600万画素で、モデル用に長辺2,048 px以下へ縮小する。
画像本体とファイル名は保存せず、EXIF情報を落としたRGB画像をローカル推論へ渡す。
画像は外部APIへ送らず、JAFFE画像をデモに同梱しない。

JAFFE評価と同一の7質問（7表情候補の選択と6成分の1〜5評価）に、顔が1つはっきり見えるかを確認する補助質問を加えた。
補助質問の結果が否定側の場合、表情候補と成分の表示を抑える。
この補助質問は顔検出器として検証したものではなく、顔の有無や人数を保証しない。

表示確率はモデルの候補間の相対確率で、本人の内面の感情の確率ではない。
JAFFEの分類正答率は4-bitで43.2%、8-bitで43.7%にとどまる。
任意画像での分類精度、補助質問の精度、人物や撮影条件をまたぐ一般化性能は未評価である。

## 実際に使用したモデル

- モデル：`mlx-community/clef-flash-4bit`
- スナップショット：`140bf7e037f5fa95a96535feca112f46c15927cf`
- 推論環境：既存の隔離MLX環境を再利用。モデルの再ダウンロードと学習は行っていない。
- ブラウザ確認用サーバ：`127.0.0.1:8023`。専用worktreeから起動し、healthのモデル名と実レスポンスのモデル名を照合した。
- 配信HTML：worktreeの `vision_demo.html` とHTTPで取得したHTMLのSHA-256が一致した。

通常の起動方法はREADMEの「Clef-Flash画像デモ」を参照する。
今回の実行では、既存MLX環境のPythonとworktreeの `src` を使用して次の起動モードを実行した。

```bash
PYTHONPATH="$PWD/src" /Users/yuya/.hermes/cache/scratch/clef-flash-8bit-venv/bin/python \
  -m systemone_workbench.cli \
  --vision-checkpoint "$HOME/.cache/huggingface/hub/models--mlx-community--clef-flash-4bit/snapshots/140bf7e037f5fa95a96535feca112f46c15927cf" \
  --host 127.0.0.1 --port 8023
```

環境名に8bitとあるが、指定したチェックポイントと応答モデルは4bitである。
この環境の絶対パスは動作確認時の記録で、アプリが固定しているパスではない。

## 実ブラウザの確認結果

JAFFE画像は使用していない。
顔写真にはNASA撮影のパブリックドメイン画像をローカルで縮小して使用した。
図形画像は動作確認用に自作した。
素材はリポジトリ外の一時領域に置き、デモには組み込んでいない。

- 写真の出典：<https://commons.wikimedia.org/wiki/File:Katherine_Johnson_1983.jpg>
- 著作者：NASA。配布ページの `PD NASA` と米国でのパブリックドメインの説明を確認した。
- 確認対象は画像入力から表示までの接続であり、この写真の判定の正しさを検証したものではない。

顔写真をブラウザで選択し、プレビュー、判定中の操作無効化、実レスポンス、7候補と6成分の表示まで確認した。
実レスポンスは `questions_evaluated: 8`、`image_media_confirmed: true` だった。
この1回のモデル推論時間は3387.4 msで、複数条件での速度評価ではない。

次の9項目を実ブラウザで確認した。

1. 幅320 pxで横方向にはみ出さない。
2. 幅390 pxで横方向にはみ出さない。
3. 幅1280 pxで横方向にはみ出さない。
4. 非対応のテキストファイルを選択すると、エラーを表示して判定を無効化する。
5. 画像を差し替えると、古い判定結果が消える。
6. 壊れたPNGを送ると、HTTP 422と画面のエラー表示になる。
7. エラー後に有効な画像を選び直して再判定できる。
8. 自作の図形画像では、顔確認が否定側となり表情分類を表示しない。
9. これらの操作中にJavaScriptのerrorとunhandledrejectionを検出しない。

図形画像の実レスポンスにも `questions_evaluated: 8` と `image_media_confirmed: true` があり、モデル推論時間は3035.1 msだった。
ブラウザからの判定リクエストは同一オリジンの `/vision/api/analyze` を使用した。
iPhone実機とSafariでの操作は未確認である。

## カメラの連続判定

同じ画面に「カメラで連続判定」と「停止」を追加した。
ブラウザの `getUserMedia` で音声なしの映像を取得し、フロントカメラを優先する。
ライブ映像から長辺1,024 px以下のJPEGを切り出し、既存の画像APIで判定する。
1件の判定が終了してから次の画像を取り込み、リクエストは重ねない。
結果には直近に判定した静止画を添え、ライブ映像の現在のフレームと区別する。

停止時は映像トラックを停止し、後から届いた処理中の結果を画面へ反映しない。
カメラ権限を待っている間に停止した場合も、後から取得された映像トラックを停止する。
ページが非表示になる操作とページを離れる操作でも停止し、自動再開はしない。
停止や権限拒否の後も、従来の画像アップロードを使用できる。

Tailscale ServeでHTTPSの `https://mac-mini-m4pro.tail1252fd.ts.net:8023/` を使用した。
バックエンドは `127.0.0.1:8023` のままで、専用worktreeから再起動した。
HTTPSからHTMLとカメラモジュールの取得、および実モデルへの画像送信を確認した。

ブラウザ検証では、NASAのパブリックドメイン写真と自作の図形をcanvasに描き、`captureStream` をカメラの代わりに使った。
これは模擬映像入力であり、実カメラや実機の権限ダイアログを確認した証拠ではない。
JPEGへの切り出し、HTTPSの画像API、MLXの画像入力、実推論、画面の結果表示は模擬応答で置き換えていない。

- 同じ写真の連続判定を行い、実モデルから画像入力ありの応答を受け取った。
- 同時に処理するリクエストが1件であること、停止後のトラック終了、新しい送信の停止、処理中の結果の抑制を確認した。
- 模擬映像を顔写真から図形へ変更すると、顔確認が否定側に変わり、7表情分類を表示しなくなることを確認した。
- ページを離れるイベントの再現で、トラックの停止と処理中の結果の抑制を確認した。
- 権限拒否の模擬エラー表示、許可待ち中の停止、停止後に取得されたトラックの解放を確認した。
- カメラ停止後の画像アップロード、画像の判定中にカメラを開始できないこと、幅320 px、390 px、1280 pxでの横方向のはみ出しがないことを確認した。
- ブラウザのJavaScriptのerrorとunhandledrejectionは検出されなかった。

カメラ制御のNodeテスト4件とPythonテスト79件が成功した。
Nodeテストは次のコマンドで、逐次処理、停止、許可待ちの取り消し、権限拒否からの再開、推論エラー時の停止を検証する。

```bash

```
